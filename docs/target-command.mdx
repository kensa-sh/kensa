The target command protocol lets a repository expose its production agent constructor without
reimplementing Kensa transport or lifecycle logic. The repository owns the session factory and
safe effect adapters. Kensa owns request validation, message framing, session dispatch, structured
errors, and shutdown.

## Python host

Create a thin launcher around the production session factory:

```python
from kensa.case import KensaCase
from kensa.target_command import serve_target

from my_agent import ProductionAgent


def open_session(case: KensaCase) -> ProductionAgent:
    return ProductionAgent(case)


raise SystemExit(serve_target(open_session))
```

The returned session implements `respond(messages)`. It may also implement `close()`. The factory,
responder, and cleanup can each be synchronous or asynchronous. A process opens no more than one
session, and the factory runs exactly once for that session.

`respond(messages)` receives the complete accepted history on every turn and returns
`ConversationResponse`. To include target-owned execution evidence, return `TargetTurnResult`:

```python
from kensa.target_command import TargetTurnResult


def respond(self, messages):
    response, evidence = self.agent.respond_with_evidence(messages)
    return TargetTurnResult(response=response, evidence=evidence)
```

## Wire contract

The protocol version is `kensa.target.v1`. Every stdin line is one JSON request. Every stdout line
is one JSON response. Stdout is reserved for protocol frames. Write repository diagnostics to
stderr.

| Request | Successful response | Purpose |
|---|---|---|
| `handshake` | `handshake` | Agree on the exact protocol version |
| `open_session` | `session_opened` | Construct one session from the supplied case |
| `turn` | `turn` | Invoke the same session with the complete message history |
| `close_session` | `session_closed` | Run optional session cleanup once |
| `shutdown` | `shutdown` | End the process cleanly |

Request IDs must be non-empty and unique within the process. Session IDs on turn and close frames
must match the opened session. Unknown fields, invalid order, malformed messages, unsupported
versions, history divergence, and non-JSON response values are rejected without invoking target
code.

Target exceptions are reported as `error` frames. The stable `code` identifies the failed boundary,
while diagnostic details remain on stderr. A target failure closes that path to later turns, so a
client must not retry an ambiguous open or turn. It may still close the session and shut down.

An explicit `shutdown` returns process status 0. EOF before shutdown closes an active session and
returns status 1.

## Pytest command target

Configure the launcher as an argument vector in `pyproject.toml`:

```toml
[tool.kensa]
target_command = ["uv", "run", "python", "scripts/kensa_target.py"]
target_timeout_s = 30
```

Kensa then supplies the function-scoped `kensa_run` fixture, so existing evals keep calling
`case.run(kensa_run)`. Each trial starts a fresh process, opens one session with the exact case,
forwards the complete conversation history, attaches returned run evidence, and closes or
terminates the process during fixture cleanup.

The command is executed directly without a shell from the directory containing `pyproject.toml`.
It inherits the pytest process environment. `target_timeout_s` bounds each protocol write, response,
and cleanup operation. Kensa never retries an open or turn after a timeout, malformed response,
crash, or ambiguous write.

A repository-defined `kensa_run` fixture overrides the configured command explicitly. Without
`target_command`, Kensa does not register the fixture and existing explicit-fixture behavior is
unchanged.

## Verify readiness

Create a repository-owned JSON case that is safe to execute against the configured target:

```json
{
  "id": "target-readiness",
  "input": "Return the readiness response for this repository"
}
```

Then run the behavioral doctor probe:

```bash
kensa doctor --target-case tests/evals/cases/target-readiness.json
```

Doctor states that it may invoke the configured model and dependencies before starting the probe.
It starts one process, completes the protocol handshake, opens the supplied case, invokes one turn,
requires a non-empty response and target-supplied execution attestation, checks the declared effect
policy, and cleans up once. Configuration, startup, handshake, session open, turn, response,
evidence, effect policy, cleanup, and timeout failures are reported separately.

An attestation with `effects="live"` fails by default. Prefer `none`, `captured`, or `sandboxed`
effects for readiness. If live effects are intentional and approved, opt in explicitly:

```bash
kensa doctor \
  --target-case tests/evals/cases/target-readiness.json \
  --allow-live-target-effects
```

Successful verification proves only the observed protocol lifecycle and the target-supplied
attestation. It does not prove which constructor or internal implementation the command uses.
Keep credentials in inherited environment variables rather than command arguments or readiness
case data.
