Kensa evals run in the Python or TypeScript test job your repository already uses. Deterministic checks require no service account or Kensa-hosted runner.

## Python and pytest

`kensa init` scaffolds a GitHub Actions workflow. A minimal Python job installs the released wheel, which already contains the platform engine:

```yaml title=".github/workflows/kensa.yml"
name: Kensa

on: [pull_request]

jobs:
  kensa:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: astral-sh/setup-uv@v7
      - run: uv sync
      - run: uv run kensa eval
```

A failed eval fails the pytest session, which fails the job - regressions block the PR.

## TypeScript and Vitest

Install `@kensa/sdk` and Vitest in the repository, then run the same command you use locally:

```yaml title=".github/workflows/kensa-typescript.yml"
name: Kensa TypeScript

on: [pull_request]

jobs:
  kensa:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: pnpm/action-setup@v6
        with:
          version: 10.28.2
      - uses: actions/setup-node@v6
        with:
          node-version: 22.17
          cache: pnpm
      - run: pnpm install --frozen-lockfile
      - run: pnpm vitest run
```

The TypeScript SDK imports `@kensa/core` directly. It does not need Python, the standalone engine, or a local service. See [TypeScript SDK](/typescript) for the evaluation shape.

## What needs credentials

| Eval uses | Needs |
|---|---|
| Deterministic assertions only (`result.trace`, plain `assert`) | Nothing |
| `judge(...)` | A provider key (`OPENAI_API_KEY` or `ANTHROPIC_API_KEY`), or `KENSA_JUDGE_RESULT` |
| Trace imports from Langfuse | `LANGFUSE_PUBLIC_KEY` + `LANGFUSE_SECRET_KEY` |

Deterministic assertions run entirely locally, so you can gate on tool usage, output shape, cost, and latency without any secrets.

If your evals call `judge(...)`, add the provider secret and (optionally) pin the model:

```yaml title="Judge step with secrets"
- run: uv run kensa eval
  env:
    OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
    KENSA_JUDGE_MODEL: gpt-5.4-mini
```

To keep judge-bearing evals green without a live model, force a deterministic verdict instead:

```yaml
- run: uv run kensa eval
  env:
    KENSA_JUDGE_RESULT: pass
```

## Reports and PR comments

Write a Markdown summary and post it as a sticky PR comment:

```yaml title="PR comment step"
- run: uv run kensa eval --markdown-report eval-report.md

- uses: marocchino/sticky-pull-request-comment@v2
  with:
    path: eval-report.md
```

Use `--json-report eval.json` when you want a machine-readable artifact to upload or feed a dashboard.

## Running on a schedule

Pull-request runs catch regressions in changed code. A nightly run catches drift from model and dependency updates that no diff touched:

```yaml title="Nightly drift check"
on:
  schedule:
    - cron: "0 7 * * *"
```

Raise `trials` on the evals you run nightly to surface flakiness that a single run would miss. See [Python SDK](/pytest) for trial verdicts.
