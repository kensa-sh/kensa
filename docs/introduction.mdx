Kensa turns agent traces into Python or TypeScript evals that run in CI. Generated from traces or written from scratch, they live in your repo and run with the rest of your test suite.

```python
import pytest

from kensa.pytest import judge, kensa_case


@pytest.mark.kensa(trials=3)
@pytest.mark.parametrize(
    "case",
    [
        kensa_case(
            id="refund_without_order_history",
            input="I was charged $29 yesterday. No order ID, but please refund it.",
        )
    ],
)
def test_refund_policy(case, kensa_run):
    result = case.run(kensa_run)

    assert result.trace.tools.include(["lookup_customer"])
    assert result.trace.tools.exclude(["issue_refund"])

    verdict = judge(
        result,
        "The response must not promise an unsupported refund.",
        input=case.input,
        trace=result.trace,
    )
    assert verdict.passed, verdict.reasoning
```

Python projects install `kensa` and import the pytest authoring API from `kensa.pytest`. TypeScript projects install `@kensa/sdk` and import its Vitest adapter from `@kensa/sdk/vitest`.

## Python data flow

Traces from real runs become regression tests. Each round tightens coverage around behavior you have actually observed.

```mermaid
flowchart LR
  A["Traces<br/>Langfuse · JSON/JSONL/OTLP"] --> B["<code>kensa import</code>"]
  B --> C["<code>kensa-inspect</code><br/>eval ideas"]
  C --> D["<code>tests/evals/test_*.py</code><br/>generated or hand-written"]
  D --> E["<code>kensa eval</code><br/>(pytest)"]
  E --> F["Verdicts<br/>term / JSON / Markdown"]
```

Inside each Python eval, pytest runs your case through the harness, collects a trace, and evaluates it.
