Kensa supports five entry points. They share evaluation semantics and artifact contracts, but each keeps your application code in its native runtime.

| Journey | Start here | Runtime boundary |
|---|---|---|
| Local evidence only | Capture or import a JSON, JSONL, or OTLP file | No observability account or provider credentials |
| Python and pytest | Install `kensa`, define `kensa_case(...)`, and provide `kensa_run` | Python runs your fixture; the bundled engine owns evaluation state |
| TypeScript and Vitest | Install `@kensa/sdk` and use `kensaTest(...)` | The SDK imports `@kensa/core` in process |
| Continuous integration | Run the same pytest or Vitest evals on pull requests | Your existing test runner owns the job |
| Connected evidence | Connect Langfuse, then import a bounded trace set | Credentials stay in environment variables |

## Local evidence only

You can build evals without a hosted service or provider credentials. Import an existing export:

```bash
kensa import --from jsonl --source spans.jsonl
kensa traces sample --json
```

If you do not have an export, [capture a local run](/tracing#capturing-traces-locally) with `kensa.instrument()`, then import the resulting JSONL. Imported evidence is minimized and redacted before it lands under `.kensa/traces/`.

## Python and pytest

Install the released Python package and follow the [quickstart](/quickstart):

```bash
uv add --dev kensa
uv run kensa init
uv run kensa eval
```

Published platform wheels contain the Kensa engine executable. Python users do not install or manage Node, pnpm, or Bun.

## TypeScript and Vitest

The TypeScript SDK runs evaluation semantics directly through `@kensa/core`:

```bash
pnpm add -D @kensa/sdk vitest
```

Continue with the [TypeScript SDK guide](/typescript) for a complete `kensaTest(...)` example.

## Continuous integration

Run Kensa with the test runner your repository already uses. Deterministic checks need no secrets. Judge-backed or connected evals receive only the credentials they need. See [CI](/ci) for Python and TypeScript jobs.

## Connected evidence

Langfuse is the supported live connection:

```bash
kensa connect langfuse
kensa import --from langfuse --since 7d --limit 200
```

`kensa connect` stores non-secret metadata under `.kensa/connections/`. It reads `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY` from the environment when it verifies access or imports traces. See [Tracing & imports](/tracing#importing-from-a-provider) for the evidence and redaction flow.
